Sección 6 Tcpdump Fundamentals

¿Qué es tcpdump?

Tcpdump captura e interpreta tramas desde una interfaz de red o desde un archivo. Funciona en sistemas Unix y puede ejecutarse desde una terminal local o una sesión SSH, por lo que es útil cuando no tenemos una interfaz gráfica.

CLI

Sin GUI. Todo ocurre en la terminal y se puede automatizar o ejecutar remotamente.

PCAP

Captura y lectura. Puede escribir paquetes en un archivo y leerlos después para repetir el análisis.

sudo

Privilegios. El acceso directo a la interfaz suele requerir root o permisos administrativos.

!Permiso primero: captura únicamente tráfico autorizado. El modo promiscuo permite ver tráfico de otros dispositivos del segmento.

Antes de capturar: localizar y comprobar

1¿Está instalado?which tcpdumpNormalmente aparece como /usr/sbin/tcpdump.
2¿Qué versión tengo?sudo tcpdump --versionConfirma tcpdump y libpcap disponibles.
3¿Qué interfaces existen?sudo tcpdump -DLista interfaces como eth0, any o lo.
Si falta el paquete:sudo apt install tcpdump

Los switches esenciales

Los switches se combinan para decidir dónde capturar, cuánto mostrar y si guardar el resultado. Esta tabla resume los que aparecen en la sección.

SwitchUsoEjemplo mental
-DLista interfaces disponibles.“¿Desde dónde puedo escuchar?”
-i eth0Selecciona la interfaz.“Captura en eth0.”
-n / -nnEvita resolver nombres; -nn tampoco traduce puertos.“Muestra IP y puerto tal cual.”
-eIncluye la cabecera Ethernet.“Muestra MAC origen y destino.”
-X / -XXContenido en hexadecimal y ASCII; -XX incluye Ethernet.“Muestra bytes y texto legible.”
-v, -vv, -vvvAumenta el detalle.“Explica más campos.”
-c 100Termina después de 100 paquetes.“No captures indefinidamente.”
-s 0Captura el paquete completo.“No cortes el contenido.”
-w archivo.pcapGuarda la captura.“Escribe para revisarla después.”
-r archivo.pcapLee una captura existente.“Reproduce el análisis.”

Leer una línea de tcpdump

11:02:35.580449 IP 172.16.146.2.48402 > 52.31.199.148.443: Flags [P.], length 37
Hora11:02:35.580449ProtocoloIPOrigen172.16.146.2:48402Destino52.31.199.148:443Flags[P.]Tamaño37 bytes
Orden recomendado: primero identifica quién habla con quién; luego mira protocolo, puerto, flags y tamaño. No intentes interpretar todos los campos a la vez.

Combinar switches en una tarea real

Capturar y versudo tcpdump -i eth0 -nnvXX -c 100

Captura en eth0, no resuelve nombres, muestra más detalle y enseña bytes Ethernet, hex y ASCII para los primeros 100 paquetes.

Guardar PCAPsudo tcpdump -i eth0 -w ~/output.pcap

Guarda la captura en vez de llenar la terminal. Vigila el espacio disponible.

Leer PCAPsudo tcpdump -r ~/output.pcap -XX

Lee el archivo y vuelve a mostrar su contenido en hexadecimal y ASCII.

Q3QuestionTraducción

Which switches start a capture without hostname resolution, verbose output, ASCII and hex contents, and the first 100 packets?

¿Qué switches capturan sin resolver nombres, con detalle, contenido ASCII/hex y los primeros 100 paquetes?

Respuesta-nnvXX -c 100
Por qué
-nn evita nombres, -v aumenta el detalle, -XX muestra Ethernet más hex/ASCII y -c 100 detiene la captura tras 100 paquetes.
Q4QuestionTraducción

Given /tmp/capture.pcap, what command reads it and shows the contents in Hex and ASCII?

Dado /tmp/capture.pcap, ¿qué comando lo lee y muestra el contenido en Hex y ASCII?

Respuestatcpdump -r /tmp/capture.pcap -X
Por qué
-r lee un archivo existente y -X muestra el contenido de los paquetes en hexadecimal y ASCII.
Q5QuestionTraducción

What tcpdump switch increases the verbosity of the output?

¿Qué switch de tcpdump aumenta el nivel de detalle?

Respuesta-v
Por qué
-v activa más detalle. También existen -vv y -vvv para niveles superiores.

Por qué
