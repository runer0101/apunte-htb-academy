Sección 7 Fundamentals Lab

Objetivo del laboratorio

Como administradores de red, necesitamos validar que el equipo puede observar el dominio de broadcast local. Practicaremos una captura pequeña y aprenderemos a conservarla para analizarla después.

01

Preparar. Comprueba que tcpdump y sus dependencias están instalados.

02

Capturar. Lista interfaces y observa el tráfico autorizado de una interfaz.

03

Conservar. Guarda la evidencia en PCAP y vuelve a leerla con otra vista.

!Regla del laboratorio: captura solo tráfico de sistemas y redes donde tengas autorización. Una captura sirve para encontrar patrones, servidores y posibles anomalías, pero debe tratarse como evidencia.

Tarea 1 · Validar la instalación

Antes de iniciar una captura, localiza el ejecutable. Si no existe, instala el paquete con el gestor de tu distribución.

lab-prep
analyst@parrot:~$ which tcpdump/usr/sbin/tcpdumpanalyst@parrot:~$ sudo tcpdump --versiontcpdump version 4.9.3libpcap version 1.9.1 (with TPACKET_V3)

La respuesta de which confirma la ruta del programa; no captura tráfico todavía.

Tarea 2 · Elegir una interfaz

Usa -D para listar los puntos desde los que tcpdump puede escuchar. En una máquina real los nombres pueden ser distintos.

interfaces
analyst@parrot:~$ sudo tcpdump -D1.eth0 [Up, Running, Connected]2.any [Up, Running]3.lo [Up, Running, Loopback]
Cómo decidir: eth0 suele representar la interfaz Ethernet, lo el tráfico local y any todas las interfaces compatibles. Elige según el alcance de tu captura.

Tarea 3 · Capturar y modificar la salida

Comienza con una captura sencilla y después combina switches para hacer la salida más útil. -nn evita resolución de nombres y puertos, -v añade detalle y -X muestra hex/ASCII.

Captura básica en eth0

capture
analyst@parrot:~$ sudo tcpdump -i eth0listening on eth0, link-type EN10MB11:20:01 IP 172.16.146.2.55260 > 172.67.1.1.443

Vista detallada para practicar

capture
analyst@parrot:~$ sudo tcpdump -i eth0 -nnvX11:20:01 IP 172.16.146.2.55260 > 172.67.1.1.4430x0000: 4500 0059 4352 4000 4006pulsa Ctrl+C para detener

Tarea 4 · Guardar la captura

Cuando quieras conservar lo observado, usa -w. La terminal deja de mostrar cada paquete porque los bytes se escriben en el archivo.

evidence
analyst@parrot:~$ sudo tcpdump -i eth0 -w ~/output.pcaplistening on eth0, link-type EN10MB, snapshot length 262144 bytes^C10 packets captured131 packets received by filter0 packets dropped by kernel

Para no capturar indefinidamente, añade por ejemplo -c 100. Vigila el espacio disponible.

Tarea 5 · Leer el PCAP

Una captura guardada se puede revisar sin volver a escuchar la red. Combina -r con -nn y -S para una lectura sin resolución y con secuencias absolutas.

review
analyst@parrot:~$ sudo tcpdump -nnS -r ~/output.pcapreading from file /home/analyst/output.pcap11:15:40.321509 IP 172.16.146.2.57236 > 172.67.1.1.443Flags [P.], seq 2751910362:2751910399, ack 946558143
Lectura: -r lee el archivo, -nn conserva IP/puertos numéricos y -S muestra números de secuencia absolutos.

Preguntas de comprobación

Cómo practicar: pulsa Ocultar respuestas para intentar resolverlas primero. Después pulsa cada tarjeta para ver la explicación y usa copiar para llevar la respuesta a HTB.
Q1

What TCPDump switch will allow us to pipe the contents of a pcap file out to another function such as 'grep'?

¿Qué switch permite enviar el contenido de un PCAP a otra función como grep?

Respuesta-l
Por qué
-l hace que la salida estándar sea line-buffered, por lo que otra herramienta puede recibirla mientras tcpdump sigue leyendo.
$ tcpdump -l -r capture.pcap | grep 443
Q2

True or False: The filter "port" looks at source and destination traffic.

Verdadero o falso: el filtro port observa el tráfico de origen y destino.

Respuestatrue
Por qué
port 443 coincide cuando el puerto 443 aparece como origen o destino.
Q3

If we wished to filter out ICMP traffic from our capture, what filter could we use? (word only, not symbol please.)

¿Qué filtro permite excluir tráfico ICMP? Escribe solo la palabra o expresión, sin símbolo.

Respuestanot icmp
Por qué
not niega la expresión BPF; así, not icmp deja fuera los paquetes ICMP.
Q4

What command will show you where / if TCPDump is installed?

¿Qué comando muestra dónde está instalado tcpdump, si existe?

Respuestawhich tcpdump
Por qué
which busca el ejecutable dentro de las rutas definidas en PATH.
Q5

How do you start a capture with TCPDump to capture on eth0?

¿Cómo se inicia una captura en la interfaz eth0?

Respuestatcpdump -i eth0
Por qué
-i eth0 selecciona la interfaz. En sistemas donde se requieren privilegios, se ejecuta como sudo tcpdump -i eth0.
Q6

What switch will provide more verbosity in your output?

¿Qué switch proporciona más detalle en la salida?

Respuesta-v
Por qué
-v aumenta el nivel de detalle. También existen -vv y -vvv.
Q7

What switch will write your capture output to a .pcap file?

¿Qué switch escribe la captura en un archivo .pcap?

Respuesta-w
Por qué
-w output.pcap escribe los paquetes en un archivo para analizarlos después.
Q8

What switch will read a capture from a .pcap file?

¿Qué switch lee una captura desde un archivo .pcap?

Respuesta-r
Por qué
-r capture.pcap abre una captura existente en lugar de escuchar una interfaz.
Q9

What switch will show the contents of a capture in Hex and ASCII?

¿Qué switch muestra el contenido de una captura en hexadecimal y ASCII?

Respuesta-X
Por qué
-X imprime los bytes en hexadecimal y su representación ASCII; -XX añade también la cabecera Ethernet.
