Sección 11 Familiarity With Wireshark

Objetivo del laboratorio

El material presenta el caso de un portátil cuyas cargas de páginas web se han vuelto lentas. Capturar tráfico mientras visitas sitios conocidos permite observar si el retraso coincide con resolución DNS, establecimiento de sesiones, retransmisiones o respuestas web demoradas. La captura es evidencia: no asumas la causa hasta examinarla.

01

Preparar. Confirma que Wireshark está instalado y localiza el host.

02

Capturar. Usa una interfaz y un filtro BPF que limite la captura al portátil.

03

Analizar. Relaciona sesiones, protocolos y datos visibles con el síntoma.

!Ética: captura solo tu propio equipo o una red para la que tengas autorización. No inspecciones credenciales ni tráfico de terceros.

Task #1 — Validar la instalación

Antes de abrir la interfaz gráfica, comprueba que el ejecutable existe. Si el comando no devuelve una ruta, instala Wireshark con el gestor de paquetes de tu sistema.

01-check-wireshark
analyst@lab:~$ which wireshark/usr/bin/wiresharkanalyst@lab:~$ wireshark &Wireshark GUI opened

En Windows o macOS, abre la aplicación desde el menú del sistema. La ruta y el nombre del proceso pueden ser distintos; lo importante es que la GUI se inicie y muestre las interfaces disponibles.

Task #2 — Conocer la interfaz de Wireshark

La command bar concentra menús, filtros y acciones; la action bar ofrece accesos rápidos para iniciar/detener capturas, abrir archivos y cambiar opciones. En la pestaña Capture aparecen las interfaces de red y sus contadores de paquetes.

02-interfaces
analyst@lab:~$ ip addr2: eth0: <BROADCAST,UP,LOWER_UP> inet 10.10.14.23/243: lo: <LOOPBACK,UP,LOWER_UP> inet 127.0.0.1/8analyst@lab:~$ tshark -D1. eth02. lo

En Capture, elige la interfaz cuyo contador aumenta cuando generas tráfico (normalmente eth0, wlan0 o una interfaz VPN). No elijas lo salvo que estés probando tráfico local.

Task #3 — Crear el capture filter

En el cuadro Capture Filter escribe host X.X.X.X, reemplazando la X por la IP del portátil. Es un filtro BPF: limita lo que se captura desde el inicio, tanto si el host es origen como si es destino.

03-host-filter
analyst@lab:~$ ip -4 addr show eth0inet 10.10.14.23/24 brd 10.10.14.255analyst@lab:~$ sudo tshark -i eth0 -f "host 10.10.14.23" -c 4Capturing on 'eth0'4 packets captured

La misma expresión BPF puede probarse con tcpdump: sudo tcpdump -ni eth0 'host 10.10.14.23'. No confundas este filtro de captura con un display filter como ip.addr == 10.10.14.23, que solo oculta filas después.

Task #4 — Generar tráfico web

Inicia la captura con el filtro activo y navega a pepsi.com y a http://apache.org. Espera a que cada página cargue; la navegación generará DNS y, según redirecciones y disponibilidad, HTTP, HTTPS y TLS.

04-web-traffic
analyst@lab:~$ curl -I https://pepsi.comHTTP/2 200 (ejemplo; puede redirigir)analyst@lab:~$ curl -I http://apache.orgHTTP/1.1 301 Moved PermanentlyLocation: https://httpd.apache.org/

Los comandos son una alternativa reproducible a hacer clic en el navegador. Los resultados reales dependen de DNS, redirecciones y del momento de la captura.

Task #5 — Detener y analizar la captura

Pulsa el botón rojo Stop en la action bar cuando ambas páginas hayan generado tráfico. En la lista de paquetes busca varias sesiones y sigue sus streams; después usa filtros de visualización como dns, http, tls o ip.addr == 10.10.14.23.

05-stop-and-review
analyst@lab:~$ tshark -r laptop-web.pcapng -Y 'dns or http or tls' -T fields -e frame.number -e ip.src -e ip.dst -e _ws.col.Protocol12 10.10.14.23 192.0.2.53 DNS29 10.10.14.23 198.51.100.20 TLS44 10.10.14.23 203.0.113.80 HTTPCapture stopped; review the saved PCAP

Múltiples handshakes TCP o múltiples identificadores de stream indican sesiones distintas. Los protocolos de aplicación dependen del PCAP: pueden aparecer DNS, HTTP/HTTPS y TLS. En texto claro pueden verse dominios, URL HTTP, métodos GET y cabeceras; HTTPS cifra el contenido de la aplicación.

Preguntas de comprobación

Las respuestas siguientes son pedagógicas y dependen de la captura: una interfaz, IP o lista de protocolos reales puede cambiar entre equipos. Conserva cada pregunta original en inglés junto con su traducción.

Q1

Are multiple sessions being established between the machine and the webserver? How can you tell?

¿Se están estableciendo varias sesiones entre la máquina y el servidor web? ¿Cómo puedes saberlo?

RespuestaYes; multiple TCP handshakes or streams show separate sessions
Por qué
Cada conexión TCP suele comenzar con un handshake y Wireshark asigna un stream. Varios handshakes o números de stream, con extremos o puertos distintos, evidencian sesiones separadas; confirma siempre en tu PCAP.
q1-sessions
analyst@lab:~$ tshark -r laptop-web.pcapng -Y 'tcp.flags.syn == 1' -T fields -e tcp.stream -e ip.src -e ip.dst0 10.10.14.23 → 198.51.100.201 10.10.14.23 → 203.0.113.80
Q2

What application-level protocols are displayed in the results?

¿Qué protocolos de la capa de aplicación aparecen en los resultados?

RespuestaDNS, HTTP/HTTPS and TLS, depending on the traffic
Por qué
La navegación necesita resolver nombres con DNS y puede producir HTTP, HTTPS y TLS. La lista exacta depende de las redirecciones, caché y sitios que se visitaron en tu captura.
q2-protocols
analyst@lab:~$ tshark -r laptop-web.pcapng -Y 'dns or http or tls' -T fields -e _ws.col.ProtocolDNSTLSHTTP (si existe tráfico HTTP sin cifrar)
Q3

Can we discern anything in clear text? What was it?

¿Podemos distinguir algo en texto claro? ¿Qué era?

RespuestaHTTP domains/URLs, GET methods and headers can be cleartext; HTTPS encrypts the content
Por qué
En HTTP puede observarse la URL, el método GET y cabeceras. TLS/HTTPS cifra la carga de la aplicación; aun así, metadatos como IP, puertos y ciertos nombres pueden seguir siendo visibles.
q3-cleartext
analyst@lab:~$ tshark -r laptop-web.pcapng -Y 'http.request' -T fields -e http.request.method -e http.request.full_uriGET http://apache.org/ (si aparece HTTP)analyst@lab:~$ tshark -r laptop-web.pcapng -Y tls -xTLS Application Data (carga cifrada; no es texto legible)
