Sección 9 Capture and Display Filters

Un método de interrogación

La lectura inicial debe ser amplia. Primero mira el PCAP completo para descubrir qué hosts, protocolos y conversaciones existen; luego aplica filtros para responder preguntas sin perder el contexto.

01

Observar. Lee el archivo sin filtro y reconoce el formato de cada línea.

02

Formular. Aísla DNS, HTTP/HTTPS, una conversación o un handshake TCP.

03

Interpretar. Usa timestamps, nombres, puertos y -X para explicar lo observado.

!Nota sobre los datos: los valores mostrados (direcciones, puertos y horas) son los del ejemplo de este laboratorio. Si utilizas otro archivo PCAP, cambiarán los resultados.

Laboratorio guiado: leer primero, filtrar después

Sustituye traffic.pcap por el nombre del archivo entregado en tu entorno. -nn evita resolver nombres y hace que la evidencia sea reproducible.

01-read-pcap
analyst@lab:~$ tcpdump -nn -r traffic.pcapreading from file traffic.pcap, link-type EN10MB11:33:58.123456 IP 172.16.146.2.443 > 95.216.26.30.54940: Flags [S]11:33:58.124001 IP 95.216.26.30.54940 > 172.16.146.2.443: Flags [S.]
  1. Leer sin filtro. Ejecuta el comando anterior y observa la primera columna: es el timestamp. Después de IP aparecen origen, destino, puerto y flags.
  2. Identificar tráfico. Distingue DNS (puerto 53), HTTP (80), HTTPS (443) y otros protocolos por sus puertos y mensajes. El sufijo [S] es SYN; [S.] es SYN/ACK.
  3. Identificar conversaciones. Agrupa los paquetes que comparten los extremos IP y puertos. Una conversación TCP queda definida por la tupla origen/destino y sus puertos.
  4. Reconocer el handshake TCP. Busca S, luego S. y finalmente . (ACK). Es el intercambio de tres pasos antes de los datos.

Interpretar una línea de tcpdump

Una línea como 11:33:58.123456 IP 172.16.146.2.443 > 95.216.26.30.54940 muestra los dos puertos usados por el primer handshake del PCAP. El dominio apache.org puede aparecer en DNS o en una cabecera HTTP; no lo inventes solo a partir de una IP.

Timestamp, DNS y nombre consultado

dns
$ tcpdump -nn -r traffic.pcap 'udp port 53'10:15:03 IP 172.16.146.20.49152 > 172.16.146.1.53: 1234+ A? apache.org. (28)

Servidor y payload con -X

server-payload
$ tcpdump -nn -X -r traffic.pcap 'tcp port 80'IP 172.16.146.20.1284 > 172.16.146.1.80: Flags [P.]GET / HTTP/1.1 ... Host: apache.orgServer: Apache/2.4.41

-X muestra hexadecimal y ASCII de la carga. Es útil para interpretar qué servidor responde, pero no descifra HTTPS: TLS oculta el contenido.

Filtros de visualización prácticos

Estos filtros se aplican al leer el PCAP (en tcpdump son expresiones BPF al final del comando). Conserva el archivo original y cambia solo la pregunta. Durante una captura nueva, la misma expresión va después de la interfaz: sudo tcpdump -i eth0 -w traffic.pcap 'port 53'; eso es un filtro de captura y descarta desde el inicio lo que no coincida.

Filtrar DNS

filter-dns
$ tcpdump -nn -r traffic.pcap 'port 53'IP 172.16.146.20.49152 > 172.16.146.1.53: A? apache.org

Filtrar HTTP y HTTPS

filter-web
$ tcpdump -nn -r traffic.pcap 'tcp port 80 or tcp port 443'IP 172.16.146.2.443 > 95.216.26.30.54940: Flags [P.]IP 172.16.146.2.51544 > 93.184.216.34.443: Flags [S]

Para una sola conversación, combina extremos: 'host 172.16.146.2 and tcp'. Para el handshake, añade 'tcp[tcpflags] & (tcp-syn|tcp-ack) != 0'; valida siempre el contexto mirando también las respuestas.

Preguntas de comprobación

Nota: las respuestas dependen del PCAP. Las siguientes usan los valores verificados del ejemplo de laboratorio; con otro archivo debes volver a contar y observar sus líneas.
Q1

What are the ports of the first TCP handshake, in ascending order?

¿Cuáles son los puertos del primer handshake TCP, en orden ascendente?

Respuesta443, 54940
Por qué
En el PCAP de referencia, el primer handshake utiliza los puertos 443 y 54940. La pregunta pide el número menor primero, por eso la respuesta es 443, 54940; no se deben ordenar por el rol del cliente o del servidor.
Q2

What is the IP address of the DNS server for the network?

¿Cuál es la dirección IP del servidor DNS de la red?

Respuesta172.16.146.1
Por qué
Las consultas DNS del ejemplo salen hacia 172.16.146.1:53; por eso esa es la IP del DNS de la red. En otro laboratorio, confirma el destino de las consultas al puerto 53.
