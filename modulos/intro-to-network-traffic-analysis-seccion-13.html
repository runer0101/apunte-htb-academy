Sección 13 Packet Inception

Objetivo: ver lo que viaja por HTTP

El laboratorio enseña a reconocer una petición GET, su respuesta 200 OK y los objetos que un servidor web entrega sin cifrar. Trabaja únicamente con capturas propias o autorizadas: una captura puede contener sesiones, imágenes y datos personales.

01

Abrir. Carga Wireshark-lab-2.pcap, sin asumir que sus valores son los de otra captura.

02

Reconstruir. Filtra HTTP, localiza GET/200 OK y usa Follow TCP Stream.

03

Extraer. Exporta objetos HTTP y valida el tipo de archivo antes de abrirlo.

!Autorización: captura y examina solo tráfico de un laboratorio, equipo o red para la que tengas permiso explícito. No recolectes credenciales de terceros.

Task #1 — Abrir la captura y filtrar HTTP

Abre Wireshark-lab-2.pcap desde File → Open. En la barra de display filter prueba http; si la disección no reconoce el protocolo, usa tcp.port == 80 como filtro de transporte. Un filtro de visualización no modifica el PCAP.

01-open-http
analyst@lab:~$ wireshark Wireshark-lab-2.pcapWireshark  filter: http or tcp.port == 80Revisa los paquetes mostrados en tu propia captura

Task #2 — GET, 200 OK y Follow TCP Stream

Busca una petición con http.request.method == "GET" y sigue la conversación asociada. Después localiza la respuesta http.response.code == 200. Clic derecho sobre un paquete → Follow → TCP Stream permite leer la petición y respuesta reensambladas; no confundas una respuesta 200 con una garantía de que el contenido sea seguro.

02-follow-stream
analyst@lab:~$ tshark -r Wireshark-lab-2.pcap -Y 'http.request.method == GET'GET /... HTTP/1.1 · revisa URI, Host y stream en Wiresharkanalyst@lab:~$ tshark -r Wireshark-lab-2.pcap -Y 'http.response.code == 200'

Task #3 — JFIF y exportación de objetos

En Packet Bytes o en la ventana de Follow TCP Stream, busca la firma ASCII JFIF. Es una pista habitual de una imagen JPEG, pero confirma siempre el tipo y el tamaño en los bytes. Para extraerla, usa File → Export → Objects → HTTP, selecciona el objeto y guárdalo en una carpeta de análisis; no hay un nombre confirmado sin inspeccionar el artefacto real.

03-find-jfif
analyst@lab:~$ tshark -r Wireshark-lab-2.pcap -Y http -x | grep -i JFIFSi aparece JFIF, vuelve al paquete/stream y exporta el objeto HTTP en la GUIanalyst@lab:~$ file objeto-extraidoResultado dependiente del objeto exportado; no se inventa aquí

Captura en vivo: contexto controlado

En una máquina de laboratorio autorizada, selecciona la interfaz ENS224 y captura solo el tiempo necesario. xfreerdp puede aparecer como contexto educativo para conectarse a un escritorio remoto de práctica, pero no pongas credenciales reales ni las expongas en esta página, en comandos compartidos o en una captura. Usa el mecanismo de secretos del laboratorio y detén la captura al terminar.

04-live-capture
analyst@lab:~$ sudo tshark -i ENS224 -f 'tcp port 80' -w live-authorized.pcapngCaptura iniciada en ENS224 · detén con Ctrl+C al completar el escenarioWireshark  filter: ip.addr == 172.16.10.2 or ip.addr == 172.16.10.20

Análisis de hosts: 172.16.10.2 y 172.16.10.20

Compara ambos hosts sin atribuir roles por la IP sola. Filtra ip.addr == 172.16.10.2 y después ip.addr == 172.16.10.20; revisa endpoints, puertos, DNS y conversaciones. El laboratorio identifica un servidor FTP y un servidor web: confirma cuál host desempeña cada papel en la captura.

05-hosts
analyst@lab:~$ tshark -r live-authorized.pcapng -Y 'ip.addr == 172.16.10.2 or ip.addr == 172.16.10.20' -T fields -e ip.src -e ip.dst -e tcp.dstportUsa la salida de tu captura para confirmar roles; no hay valores predeterminados

FTP: control, autenticación y datos

En el servidor FTP, separa el canal de control del canal de datos. Usa ftp para comandos/respuestas, ftp.request.command para ver acciones como USER, PASS, LIST o RETR, y ftp-data para el contenido transferido. Comprueba si la autenticación fue anónima o con usuario antes de concluir; FTP sin cifrar puede revelar credenciales. Para archivos fragmentados, permite el reensamblado TCP y sigue el stream de datos, siempre en el laboratorio autorizado.

06-ftp
Wireshark  filter: ftpWireshark  filter: ftp.request.command == "USER"Wireshark  filter: ftp-dataConfirma USER/PASS, respuesta del servidor y stream de datos en tu PCAP

HTTP: servidor, aplicación y métodos

Para el servidor web, inspecciona http.host, http.server, URI y cabeceras. Relaciona la aplicación con los métodos observados: GET recupera recursos, POST envía datos y otros métodos pueden revelar una API o una operación administrativa. Elige el filtro más estrecho que responda a la pregunta del análisis.

07-http-methods
Wireshark  filter: http.request and ip.addr == 172.16.10.2Wireshark  filter: http.request.method == "GET" or http.request.method == "POST"Anota Host, servidor, URI y método observados; no generalices fuera de la captura

Tráfico TCP del cliente

Para aislar el tráfico TCP del cliente, combina la IP confirmada del cliente con tcp; para una conversación concreta añade tcp.stream eq N. En tshark puedes usar -Y para el filtro de visualización. El valor de N, los puertos y cualquier nombre de archivo deben leerse de la captura, no suponerse.

08-client-tcp
analyst@lab:~$ tshark -r Wireshark-lab-2.pcap -Y 'ip.src == CLIENT_IP and tcp'Wireshark  filter: ip.addr == CLIENT_IP and tcpSustituye CLIENT_IP por la IP confirmada en tu captura autorizada

Preguntas de comprobación

Cómo usar estas tarjetas: conserva la pregunta original en inglés, revisa su traducción y busca el dato en la evidencia. Estas respuestas quedan pendientes porque no se proporcionaron los artefactos del laboratorio.
Q1

What was the filename of the image that contained a certain Transformer Leader? (name.filetype)

¿Cuál era el nombre de archivo de la imagen que contenía a cierto líder de los Transformers? (nombre.extensión)

RespuestaRevisar en Wireshark-lab-2.pcap / captura viva
Por qué
No se confirma un nombre sin el PCAP. Filtra http, usa File → Export → Objects → HTTP, identifica la imagen relevante y copia su nombre exacto con extensión. Comprueba también la firma JFIF en bytes/stream.
q1
Wireshark  filter: http or tcp.port == 80Export Objects → HTTP · nombre pendiente de la captura autorizada
Q2

Which employee is suspected of performing potentially malicious actions in the live environment?

¿Qué empleado es sospechoso de realizar acciones potencialmente maliciosas en el entorno en vivo?

RespuestaRevisar en Wireshark-lab-2.pcap / captura viva
Por qué
No se inventa una identidad. En la captura viva autorizada, correlaciona IP/host del cliente, autenticación FTP, solicitudes HTTP, streams TCP y contexto del laboratorio; después verifica el nombre del empleado en la evidencia o en los registros permitidos.
q2
Wireshark  filter: ftp.request.command or http.requestCorrelaciona el host observado con los registros autorizados · identidad pendiente
