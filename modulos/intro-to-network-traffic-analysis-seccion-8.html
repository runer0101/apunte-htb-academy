Sección 8 Tcpdump Packet Filtering

Filtrar antes de analizar

Una expresión de filtro le dice a tcpdump qué paquetes mostrar o guardar. Los filtros usan la sintaxis de Berkeley Packet Filter (BPF) y pueden combinarse para construir preguntas precisas.

01

Reducir ruido. Observa solo un host, una red, un protocolo o un puerto.

02

Componer. Usa and, or y not para expresar condiciones.

03

Conservar contexto. Aplica la misma expresión al capturar o al leer un PCAP.

!Autorización: captura y analiza únicamente tráfico de sistemas y redes donde tengas permiso. Un filtro reduce lo que ves; no convierte una captura autorizada en una actividad autorizada.

Pre-capture frente a post-capture

La expresión puede ir al final de ambos comandos. Con -i filtra mientras captura; con -r filtra la lectura de un archivo que ya existe.

Pre-capture: solo HTTPS de un host

live-filter
analyst@parrot:~$ sudo tcpdump -i eth0 -nn 'host 10.10.20.1 and port 443'listening on eth0, link-type EN10MB14:12:01 IP 10.10.20.1.51544 > 172.67.1.1.443

Post-capture: consulta un PCAP

read-filter
analyst@parrot:~$ tcpdump -nn -r capture.pcap 'host 10.10.20.1 and port 443'reading from file capture.pcap, link-type EN10MB14:12:01 IP 10.10.20.1.51544 > 172.67.1.1.443
Advertencia: el filtro pre-capture descarta paquetes que no coincidan desde el principio y puede ahorrar recursos, pero no podrás recuperar después lo que no guardaste. El post-capture deja intacto el PCAP y permite probar expresiones distintas.

Tabla de filtros BPF

Estos primitivas pueden usarse solas o dentro de una expresión mayor. Si no indicas src o dst, muchos calificadores coinciden con ambos sentidos.

FiltroQué seleccionaEjemplo
hostOrigen o destino de una dirección.host 10.10.20.1
src / dstSolo dirección de origen o destino.src host 10.10.20.1
protoUn protocolo de red o transporte.proto 6 / tcp
portPuerto de origen o destino.port 53
portrangeUn intervalo de puertos.portrange 8000-8080
less / greaterPaquetes menores o mayores que N bytes.greater 1000

De lo específico a lo compuesto

Practica cada familia de filtros y comprueba cómo cambia la salida. Las comillas protegen los operadores y hacen legible la expresión completa para el shell.

Host, dirección y protocolo

selectors
$ tcpdump -nn -r capture.pcap 'host 10.10.20.1'IP 10.10.20.1.51544 > 172.67.1.1.443$ tcpdump -nn -r capture.pcap 'dst host 10.10.20.1 and tcp'IP 172.67.1.1.443 > 10.10.20.1.51544$ tcpdump -nn -r capture.pcap 'src host 10.10.20.1 and proto 6'IP 10.10.20.1.51544 > 172.67.1.1.443

Puertos y tamaños

ports-size
$ tcpdump -nn -r capture.pcap 'port 53 or portrange 8000-8080'IP 10.10.20.1.53122 > 10.10.20.53.53$ tcpdump -nn -r capture.pcap 'greater 1000'IP 10.10.20.1.51544 > 172.67.1.1.443: length 1420$ tcpdump -nn -r capture.pcap 'less 128'IP 10.10.20.1.53 > 10.10.20.53.53: length 96

Operadores, ASCII y TCP SYN

and exige que ambas condiciones sean verdaderas, or acepta cualquiera y not invierte el resultado. Para buscar texto visible, combina -A con -l y grep; recuerda que el contenido puede estar cifrado.

Lógica: tráfico web nuevo, no ICMP

logic
$ tcpdump -nn -r capture.pcap 'tcp port 80 or tcp port 443'IP 10.10.20.1.51544 > 172.67.1.1.443$ tcpdump -nn -r capture.pcap 'not icmp and host 10.10.20.1'IP 10.10.20.1.51544 > 172.67.1.1.443

ASCII y grep sobre un PCAP

payload
$ tcpdump -A -l -r capture.pcap 'tcp port 80' | grep -i 'user-agent'User-Agent: curl/8.0
Nota: -A imprime la carga en ASCII y -l hace que la salida sea line-buffered para que grep reciba cada línea. No confundas -A con descifrar TLS.
tcp-syn
$ sudo tcpdump -nn -i eth0 'tcp[tcpflags] & tcp-syn != 0'15:03:11 IP 10.10.20.1.51544 > 172.67.1.1.443: Flags [S], seq 1234

El filtro TCP SYN usa una operación bit a bit: muestra paquetes cuyo bit SYN está activo. Para excluir ACK y ver el inicio de conexiones, puede añadirse and not tcp[tcpflags] & tcp-ack != 0.

Preguntas de comprobación

Cómo practicar: pulsa Ocultar respuestas para intentar resolverlas primero. Después pulsa cada tarjeta para ver la explicación y usa copiar para llevar la respuesta a HTB.
Q1

Which host filter would match traffic to or from 10.10.20.1?

¿Qué filtro de host coincide con tráfico hacia o desde 10.10.20.1?

Respuestahost 10.10.20.1
Por qué
host busca la dirección tanto en origen como en destino. Usa src host o dst host para limitar el sentido.
Q2

Which operator matches either of two filter expressions?

¿Qué operador coincide con cualquiera de dos expresiones?

Respuestaor
Por qué
or devuelve los paquetes que cumplen la primera o la segunda condición, por ejemplo port 80 or port 443.
Q3

True or False: the filter "port" checks both source and destination ports.

Verdadero o falso: el filtro port comprueba los puertos de origen y destino.

Respuestatrue
Por qué
Sin el calificador src o dst, port 443 coincide cuando 443 aparece en cualquiera de los dos extremos.
